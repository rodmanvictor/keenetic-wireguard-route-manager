# Архитектура проекта

Проект разделён по ответственности. Рабочий код не лежит в корне репозитория.

```text
keenetic-router/
├── src/keenetic_router/       Python-пакет
│   ├── core/router.py          подключение к KeeneticOS и операции с маршрутами
│   └── apps/                  пользовательские приложения
│       ├── tui.py             терминальное меню kwtui
│       ├── cli.py             команда kwan
│       ├── importer.py        команда kwimport
│       └── desktop.py         desktop-интерфейс
├── integrations/chrome/       Chrome-расширение и Native Messaging host
├── integrations/systemd/      шаблоны локального таймера обновления
├── tools/                     вспомогательные утилиты, не являющиеся основным UI
├── examples/                  примеры входных файлов
├── scripts/                   установка, сборка и проверки проекта
├── docs/                      устойчивая документация
├── tests/                     автоматические тесты
└── var/                       локальные отчёты и SQLite-базы, вне Git
```

## Ядро

`src/keenetic_router/core/router.py` — единственное место для низкоуровневых Telnet/SSH-команд, поиска WireGuard-интерфейсов, DNS-разрешения и работы с маршрутами. `core/profiles.py` хранит один несекретный профиль роутера, `core/onboarding.py` диагностирует транспорт и компоненты, `core/wireguard.py` проверяет и импортирует `.conf`/QR. Все интерфейсы используют эти модули, а не реализуют собственное подключение.

Рабочий транспорт выбирается не настройкой наугад, а реальным входом: сначала SSH, затем Telnet с попыткой выполнить `service ssh`. Telnet остаётся аварийным режимом; WireGuard-ключи через него не передаются.

`src/keenetic_router/services/` содержит SQLite-реестр доменов, обновление DNS-маршрутов и обратную инвентаризацию: маршрут может иметь несколько независимых источников, поэтому общий IP не теряет маршрут при отключении одного сервиса.

## Интерфейсы

- `kwtui` запускает интерактивное терминальное меню.
- `kwan` запускает CLI для добавления, просмотра и удаления маршрутов.
- `kwimport` импортирует файлы в формате Windows `route add`.
- `keenetic-desktop` — desktop-интерфейс с первым подключением, компонентами, WireGuard-импортом и доменами.

Запускаторы в `bin/` сохраняют совместимость с привычными командами и передают выполнение в Python-пакет из `src/`.

## Интеграции и данные

Chrome-расширение не содержит логики управления роутером: оно передаёт запрос native host, а тот использует общее ядро. В `var/` хранится SQLite-база автоматического обновления маршрутов; папка специально исключена из Git. Локальный user-timer systemd запускает обновление раз в шесть часов.
