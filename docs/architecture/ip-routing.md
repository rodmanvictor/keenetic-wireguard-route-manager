# Маршрутизация IPv4 и IPv6

PackeTech работает с обоими семействами адресов. Для каждого включённого
домена системный resolver запрашивает записи A и AAAA. Ответы превращаются в
точные маршруты, поэтому через VPN уходит только адрес выбранного сайта:

- IPv4 — `/32`, команда KeeneticOS `ip route … 255.255.255.255 … WireguardN`;
- IPv6 — `/128`, команда KeeneticOS `ipv6 route …/128 WireguardN`.

Перед пакетным обновлением приложение один раз читает `show ip route` и
`show ipv6 route`, а затем применяет разницу. Существующий маршрут на нужном
туннеле не создаётся повторно. Маршрут на другом WireGuard-интерфейсе сначала
снимается и затем создаётся на выбранном интерфейсе.

SQLite хранит IPv4 и IPv6 одинаково: адрес DNS, сеть маршрута и все активные
владельцы остаются отдельными строками. Поэтому общий `/32` или `/128` не
удаляется, пока он нужен хотя бы одному домену или опубликованному списку.
Инвентаризация объединяет результаты обеих команд `show … route`; официальный
`goog.json` сопоставляется по `ipv4Prefix` и `ipv6Prefix`.

## Условия работы IPv6

Наличие AAAA-записи у сайта недостаточно. Выбранный WireGuard-профиль должен
иметь IPv6-адрес и peer `AllowedIPs`, разрешающий нужный диапазон. При импорте
`.conf` или QR PackeTech теперь применяет первый `Address` каждого семейства и
все IPv4/IPv6 `AllowedIPs`.

Если VPN-провайдер не выдаёт IPv6 внутри туннеля, IPv4 продолжит работать, а
KeeneticOS отклонит или не сможет использовать IPv6-маршрут. Это свойство
конкретного VPN-профиля, а не DNS или SQLite.

## Удаление

Для IPv4 используется `no ip route`, для IPv6 — `no ipv6 route`. Отключение
домена снимает только его владельца и удаляет точный маршрут лишь при отсутствии
других владельцев. Автообновление не удаляет старые DNS-ответы само: временная
смена CDN не должна неожиданно оборвать доступ.
