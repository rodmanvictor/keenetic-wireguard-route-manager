# Подключение и первичная настройка

## Профиль роутера

Первая версия приложения управляет одним профилем `default`. В нём хранятся
адрес роутера, логин, порты SSH/Telnet, последний рабочий транспорт и пароль
администратора. Это осознанное поведение для повторных подключений без ввода
пароля.

Расположение `config.json`:

- Linux: `$XDG_CONFIG_HOME/keenetic-route-manager/` или `~/.config/keenetic-route-manager/`.
- Windows: `%APPDATA%\\KeeneticRouteManager\\config.json`.

В Linux файл получает режим `600`, каталог — `700`. Пароль хранится без
шифрования и доступен процессам текущего пользователя операционной системы.

Существующая локальная `.env` остаётся совместимой. При отсутствии сохранённого
пароля CLI спрашивает его через скрытый ввод. Для неинтерактивного запуска
разрешена переменная окружения через `--password-env`; отдельного аргумента с
паролем нет, чтобы секрет не попадал в историю shell и список процессов.

После успешного подключения Linux-приложение создаёт пользовательский
`paketych-sync.timer`, а Windows-приложение — задачу `Paketych route sync` в
Планировщике заданий. Обе схемы обновляют домены каждые 6 часов. Ошибка
локального планировщика не блокирует ручную работу GUI.

## Автоматический выбор транспорта

`bootstrap_router` выполняет последовательность:

1. Проверяет реальную аутентификацию по SSH.
2. При ошибке подключается по Telnet с теми же учётными данными.
3. Выполняет `service ssh` и `system configuration save`.
4. Повторяет полноценную SSH-аутентификацию и подтверждает новый вход.
5. Если SSH всё равно недоступен, оставляет Telnet как медленный режим и показывает инструкцию.

Одной проверки открытого TCP-порта недостаточно: рабочим считается только аутентифицированный сеанс, принявший команды KeeneticOS.

Отдельный TCP-probe перед SSH-входом намеренно не используется: на реальном
Keenetic быстро закрытая пробная сессия может заставить SSH-сервер сбросить
следующее подключение.

Если недоступны оба протокола, приложение не может исправить ситуацию удалённо. Пользователь должен открыть веб-интерфейс KeeneticOS, установить/включить «Сервер SSH» либо разрешить Telnet из домашней сети, после чего повторить подключение.

## Компоненты KeeneticOS

SSH и WireGuard — компоненты прошивки KeeneticOS. Это не пакеты Linux/Entware. Приложение читает `components list` и различает три состояния: установлен, доступен для установки, недоступен для данной модели/версии.

Установка выполняется командами в контексте `components`:

```text
install ssh
install wireguard
commit
```

`commit` способен скачать другую сборку KeeneticOS, оборвать соединение и перезагрузить устройство. CLI требует одновременно `--install-components --confirm-reboot`, а desktop показывает отдельное предупреждение и кнопку подтверждения. Фоновая синхронизация никогда не устанавливает компоненты.

## Граница Telnet

Telnet передаёт данные без шифрования. Он допустим только в доверенной домашней сети для запуска SSH, диагностики и аварийного управления обычными маршрутами. Импорт приватного и preshared-ключа WireGuard через Telnet программно запрещён.
