# Ручное управление маршрутами

## Подготовка

Старая локальная установка может хранить учётные данные в `.env`, исключённой из Git. Публичный CLI и desktop сохраняют профиль вместе с паролем в пользовательском JSON с правами `600` на POSIX-системах. Пароль не зашифрован: пользователь с доступом к этой учётной записи компьютера сможет его прочитать.

```bash
cp .env.example .env
```

Для разработки установите пакет в локальное окружение:

```bash
.venv-build/bin/python -m pip install -e .
```

## Терминал

```bash
packetech setup
packetech status
packetech tui
packetech list
packetech add example.com --tunnel wg1
packetech remove example.com --tunnel wg1
kwimport examples/windows-routes.txt --tunnel wg1 --dry-run
```

`wg1` — короткое имя интерфейса; полное имя `Wireguard1` также принимается. Перед массовым изменением всегда начинайте с `--dry-run`, если команда его поддерживает.

## Автообновление доменов

Добавление домена через `packetech add` одновременно добавляет текущие маршруты и сохраняет домен для дальнейших обновлений. Просмотр и ручной запуск:

```bash
packetech watch list
packetech sync --dry-run
packetech sync
```

Включить локальный запуск в `00:00`, `06:00`, `12:00` и `18:00`:

```bash
./scripts/install-route-sync-timer.sh
```

Если компьютер был выключен в момент запуска, systemd выполнит пропущенное обновление после следующего запуска системы. Состояние и журнал хранятся в `var/route-sync.sqlite3`.

## Desktop-интерфейс

Desktop-интерфейс написан на Flet и работает поверх той же SQLite-базы и SSH-ядра, что CLI. Первый экран принимает адрес, логин и пароль, диагностирует SSH/Telnet и при необходимости запускает SSH. После входа приложение показывает favicon, домен, выбранный туннель и источники добавления. Фильтр «Только Chrome» предназначен для периодической чистки временных сайтов.

Над списком нет отдельного поиска и фильтра источников: это строка быстрого
добавления с квадратной кнопкой `+`. Она принимает как `example.com`, так и
полный URL с протоколом, портом, путём и параметрами. В SQLite сохраняется
только извлечённый hostname. Enter равнозначен нажатию `+`.

Имена VPN читаются из поля `description` интерфейса KeeneticOS. В основном UI
показывается это имя, а `wgN` и `WireguardN` используются только как техническая
подпись и ключ маршрутизации.

Раздел «Настройка VPN» показывает живые `up/down` состояния. Переименование
меняет `description` интерфейса и сохраняет конфигурацию. Включение и отключение
выполняет `up/down`; перед отключением интерфейс показывает количество связанных
сайтов. Удаление `no interface WireguardN` доступно только для профиля без
активных доменов и требует отдельного подтверждения.

DNS IP и CIDR не участвуют в основном сценарии. Они доступны по кнопке
«Технические данные» в отдельном окне с пояснениями:

- DNS IP — точный IPv4- или IPv6-адрес из последнего DNS-запроса;
- CIDR — диапазон IPv4 или IPv6 из опубликованного списка сервиса.

Favicon загружается best-effort через Google S2 только по имени домена. При
ошибке остаётся локальная заглушка с первой буквой.

После установки пакета:

```bash
packetech
```

Установочный `.deb` добавляет ярлык `PackeTech` в системное меню приложений. Файл
`integrations/desktop/keenetic-router.desktop` остаётся совместимым ярлыком для
запуска из исходников.

Linux-сборка создаётся через PyInstaller и упаковывается в `.deb` и переносимый архив:

```bash
./scripts/build-linux.sh
```

## Chrome-расширение

- пользователь нажимает **Chrome** → **Установить расширение** в desktop-приложении;
- `chrome_installer.py` обнаруживает Chrome, копирует пакетные ресурсы в
  пользовательский каталог и регистрирует native messaging host;
- отдельный `packetech-chrome-host` загружает сохраненный профиль роутера и ту
  же SQLite-базу, что GUI и CLI;
- постоянный ключ в manifest фиксирует ID расширения
  `fggdjnagagddkbpglpnhhjopgcodnham`, поэтому копировать ID вручную больше не
  нужно;
- Windows использует HKCU NativeMessagingHosts, Linux — пользовательский каталог
  Chrome, macOS — `~/Library/Application Support/Google/Chrome/NativeMessagingHosts`;
- Chrome оставляет пользователю обязательное действие: включить режим
  разработчика и один раз выбрать открытую PackeTech папку через
  «Загрузить распакованное расширение».

Расширение отправляет домен активной вкладки и выбранные пользователем домены
неудачных ресурсов в native host с источником `chrome`, а после синхронизации
перезагружает вкладку. Туннель не зашит в JavaScript: native host выбирает
последний используемый туннель, а для пустой базы проверяет живые интерфейсы
Keenetic и предпочитает включенный.

Manifest V3 service worker наблюдает завершённые запросы через неблокирующий
`webRequest` и временно группирует ошибки по вкладке в `storage.session`.
Политика намеренно исключает HTTP 404, отменённые запросы, блокировки клиента,
CSP и ошибки сертификата. Popup показывает только ошибки доступа 403/451,
сетевые/DNS-сбои и ограниченный набор шлюзовых/CDN 5xx; каждый связанный домен
включается отдельной галочкой. Содержимое страниц и запросов не сохраняется.

Совместимые исходные entry points сохранены в `integrations/chrome/`. После
изменения manifest, popup, service worker или иконок пакетная копия обновляется
командой `npm run sync:chrome`. Она устанавливает адаптивные иконки Пакетыча
для popup и отдельный белый знак маршрута на прозрачном фоне для тесного слота
в тулбаре Chrome.

## Источники домена

SQLite хранит источники как независимые связи, а не одно перезаписываемое поле:

- `chrome` — временно добавлен из расширения;
- `desktop` — добавлен из графического приложения;
- `terminal` — добавлен из `packetech tui`;
- `cli` — добавлен командой `packetech`;
- `rucens:<service>` — добавлен из каталога rucens.

Один домен может иметь несколько источников. Снятие метки Chrome не отключает домен, если он также принадлежит rucens или был добавлен вручную. Когда отключён последний источник, приложение снимает DNS-владение и удаляет с Keenetic только точные IPv4 `/32` и IPv6 `/128` без других активных владельцев. Общие IP, а также маршруты с точным владельцем из rucens или инвентаризации, сохраняются. История DNS остаётся в SQLite.
