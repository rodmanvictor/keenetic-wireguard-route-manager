# Ручное управление маршрутами

## Подготовка

Старая локальная установка может хранить учётные данные в `.env`, исключённой из Git. Публичный CLI и desktop сохраняют профиль вместе с паролем в пользовательском JSON с правами `600` на POSIX-системах. Пароль не зашифрован: пользователь с доступом к этой учётной записи компьютера сможет его прочитать.

```bash
cp .env.example .env
```

Для разработки установите пакет в локальное окружение:

```bash
.venv-build/bin/python -m pip install -e .
```

## Терминал

```bash
kwan setup
kwan status
kwtui
kwan list
kwan add example.com --tunnel wg1
kwan remove example.com --tunnel wg1
kwimport examples/windows-routes.txt --tunnel wg1 --dry-run
```

`wg1` — короткое имя интерфейса; полное имя `Wireguard1` также принимается. Перед массовым изменением всегда начинайте с `--dry-run`, если команда его поддерживает.

## Автообновление доменов

Добавление домена через `kwan add` одновременно добавляет текущие маршруты и сохраняет домен для дальнейших обновлений. Просмотр и ручной запуск:

```bash
kwan watch list
kwan sync --dry-run
kwan sync
```

Включить локальный запуск в `00:00`, `06:00`, `12:00` и `18:00`:

```bash
./scripts/install-route-sync-timer.sh
```

Если компьютер был выключен в момент запуска, systemd выполнит пропущенное обновление после следующего запуска системы. Состояние и журнал хранятся в `var/route-sync.sqlite3`.

## Desktop-интерфейс

Desktop-интерфейс написан на Flet и работает поверх той же SQLite-базы и SSH-ядра, что CLI. Первый экран принимает адрес, логин и пароль, диагностирует SSH/Telnet и при необходимости запускает SSH. После входа приложение показывает favicon, домен, выбранный туннель и источники добавления. Фильтр «Только Chrome» предназначен для периодической чистки временных сайтов.

Над списком нет отдельного поиска и фильтра источников: это строка быстрого
добавления с квадратной кнопкой `+`. Она принимает как `example.com`, так и
полный URL с протоколом, портом, путём и параметрами. В SQLite сохраняется
только извлечённый hostname. Enter равнозначен нажатию `+`.

Имена VPN читаются из поля `description` интерфейса KeeneticOS. В основном UI
показывается это имя, а `wgN` и `WireguardN` используются только как техническая
подпись и ключ маршрутизации.

Раздел «Настройка VPN» показывает живые `up/down` состояния. Переименование
меняет `description` интерфейса и сохраняет конфигурацию. Включение и отключение
выполняет `up/down`; перед отключением интерфейс показывает количество связанных
сайтов. Удаление `no interface WireguardN` доступно только для профиля без
активных доменов и требует отдельного подтверждения.

DNS IP и CIDR не участвуют в основном сценарии. Они доступны по кнопке
«Технические данные» в отдельном окне с пояснениями:

- DNS IP — точный IPv4-адрес из последнего DNS-запроса;
- CIDR — диапазон IPv4 из опубликованного списка сервиса.

Favicon загружается best-effort через Google S2 только по имени домена. При
ошибке остаётся локальная заглушка с первой буквой.

После установки пакета:

```bash
keenetic-desktop
```

Установочный `.deb` добавляет ярлык `PackeTech` в системное меню приложений. Файл
`integrations/desktop/keenetic-router.desktop` остаётся совместимым ярлыком для
запуска из исходников.

Linux-сборка создаётся через PyInstaller и упаковывается в `.deb` и переносимый архив:

```bash
./scripts/build-linux.sh
```

## Chrome-расширение

- распакованное расширение: `integrations/chrome/extension/`;
- native host: `integrations/chrome/native_host/host.py`;
- установка native host: `./scripts/install-native-host-linux.sh <EXTENSION_ID> .venv-chrome/bin/python`.

Пользовательская установка в Linux:

1. Скачать и распаковать исходный код последнего GitHub Release.
2. Открыть `chrome://extensions` и включить режим разработчика.
3. Нажать «Загрузить распакованное расширение» и выбрать
   `integrations/chrome/extension/`.
4. Скопировать 32-символьный ID с карточки расширения.
5. В корне распакованного проекта выполнить:

```bash
python3 -m venv .venv-chrome
.venv-chrome/bin/python -m pip install -e .
./scripts/install-native-host-linux.sh <ID_ИЗ_CHROME> .venv-chrome/bin/python
```

6. Вернуться в Chrome, включить переключатель расширения и закрепить его значок.

Расширение намеренно минимальное: оно получает только домен активной вкладки, отправляет его native host с источником `chrome`, добавляет текущие DNS-маршруты через `wg1` и перезагружает вкладку. Фоновый перехват запросов, доступ ко всем URL и сбор вспомогательных CDN-доменов удалены.

Native host применяет изменение через общий сервис синхронизации. Домен остаётся в шестичасовом автообновлении и виден в desktop-приложении с меткой Chrome.

После изменения файлов распакованного расширения откройте `chrome://extensions`, включите режим разработчика и нажмите «Перезагрузить» на карточке `PackeTech · открыть сайт`. Chrome не перезагружает измененный Manifest V3 автоматически.

Если на карточке написано `Off`, сначала включите переключатель справа. Кнопка с
круглой стрелкой только перечитывает файлы уже включённого расширения и не
заменяет этот переключатель. После каждой повторной загрузки распакованной
папки проверьте её ID и заново привяжите native host именно к нему:

```bash
./scripts/install-native-host-linux.sh <ID_ИЗ_CHROME> .venv-chrome/bin/python
```

ID в `allowed_origins` файла
`~/.config/google-chrome/NativeMessagingHosts/com.keenetic.router.host.json`
должен точно совпадать с ID карточки. Иначе popup откроется, но Chrome не
разрешит ему связаться с локальным помощником.

## Источники домена

SQLite хранит источники как независимые связи, а не одно перезаписываемое поле:

- `chrome` — временно добавлен из расширения;
- `desktop` — добавлен из графического приложения;
- `terminal` — добавлен из `kwtui`;
- `cli` — добавлен командой `kwan`;
- `rucens:<service>` — добавлен из каталога rucens.

Один домен может иметь несколько источников. Снятие метки Chrome не отключает домен, если он также принадлежит rucens или был добавлен вручную. Когда отключён последний источник, приложение снимает DNS-владение и удаляет с Keenetic только точные `/32`-маршруты без других активных владельцев. Общие IP, а также маршруты с точным владельцем из rucens или инвентаризации, сохраняются. История DNS остаётся в SQLite.
