# Обратная инвентаризация маршрутов

Первый импорт создаёт в `var/route-sync.sqlite3` снимок уже существующих маршрутов Keenetic. Он ничего не меняет на роутере.

```bash
packetech inventory import
packetech inventory summary
packetech inventory lookup 104.18.41.42
```

## Источники и достоверность

- Файлы сервисов из `vitalygashkov/rucens` дают точные сопоставления CIDR с именем сервиса.
- Опубликованные диапазоны Google (`goog.json`) и Telegram (`cidr.txt`) дают точные сопоставления с организацией, но не с отдельным продуктом.
- Маршруты без точного совпадения помечаются `preserved:unclassified`. Автоматизация не удаляет их.

Файлы, которые ты вспоминал, — не `robots.txt`: это JSON/TXT со списками диапазонов, а также Windows batch-файлы `route add` из GitHub.

## Общие IP и безопасное отключение

У маршрута может быть несколько владельцев. Например, один Cloudflare-диапазон может относиться одновременно к ChatGPT, DeepL и другим сервисам. База хранит отдельную связь для каждого источника.

Такая же many-to-many логика действует для доменов: один домен может одновременно иметь источники Chrome, Desktop, CLI и rucens. Поэтому удаление временной Chrome-метки не затрагивает постоянное добавление того же домена.

При отключении сервиса сначала снимается только его связь с маршрутом. Физически удалить маршрут можно лишь когда одновременно выполнены оба условия:

1. у маршрута не осталось активных владельцев;
2. другой активный маршрут не покрывает тот же адрес через тот же туннель.

При обычном шестичасовом обновлении автоматизация добавляет новые IPv4 и IPv6, но старые DNS-IP сама не удаляет: временное исчезновение адреса из DNS не должно ломать рабочий маршрут. Явное отключение домена — отдельный случай: его точные `/32` и `/128` DNS-маршруты удаляются, только если после снятия владельца у них не осталось других активных точных владельцев.

Разовое удаление неопознанных маршрутов — отдельная опасная операция. Перед ней создаётся JSON-копия списка в `var/backups/`. Для Telnet лучше удалять короткими пачками: результат каждой успешно принятой роутером команды сразу сохраняется в SQLite, поэтому следующий запуск продолжит с оставшихся маршрутов.

```bash
packetech inventory purge-unclassified --dry-run
packetech inventory purge-unclassified --confirm
# например по 10 маршрутов за запуск
packetech inventory purge-unclassified --confirm --limit 10
```

В `packetech tui` пункт «Сервисы и домены» показывает отдельно восстановленные сервисы из существующих маршрутов и домены регулярного DNS-обновления. После инвентаризации известные однозначные соответствия автоматически переносятся в DNS-наблюдение с тем же туннелем; неизвестные сервисы остаются только в карте маршрутов.

## Быстрое добавление из rucens

В `packetech tui` пункт «Быстро добавить сервисы из rucens» показывает нумерованный каталог. Можно выбрать несколько пунктов через пробел или запятую, например `3 7, 12`.

Для выбранного сервиса применяются его статические CIDR из `rucens/*.bat`. Для сервисов с явно заданными доменами добавляется второй источник — DNS-наблюдение раз в шесть часов. Например, `chatgpt` добавляет диапазоны из `chatgpt.bat` и отслеживает `chatgpt.com` с `chat.openai.com`. Новый DNS-адрес дополняет маршруты, а не заменяет список rucens.
